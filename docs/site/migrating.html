Moving from scikit-learn

The Python package follows scikit-learn's shape: fit returns the estimator, predict, transform, score and fit_predict work as expected, and get_params, set_params and clone work. A scikit-learn scaler can sit in front of one of ours in a Pipeline, and cross_val_score and grid search run on them; the interop tests cover this. The differences below are the ones that will change a result or stop code from running.

Names that differ

scikit-learntpt-ml-provenNotes
random_stateseedEvery estimator with randomness. The default is 0, so a fit is repeatable without setting it.
n_init (KMeans)not availableOne start only. Run with several seeds and keep the lowest inertia_ if you want the same effect.
n_jobs (KMeans)threadsDefaults to 1. Results match across thread counts.
C (LogisticRegression)CSame meaning: the inverse of the penalty strength.

Defaults that differ

These are the ones most likely to change a result without an error.

  • Tree depth. DecisionTreeClassifier, DecisionTreeRegressor and GradientBoostingRegressor default to max_depth=3, and the random forests to max_depth=10. scikit-learn leaves depth unlimited by default. Set max_depth explicitly on both sides before you compare.
  • Forest depth. Same point, for RandomForestClassifier and RandomForestRegressor.
  • KMeans start. Ours is one k-means++ start from the seed. For a given seed the labels are reproducible, but they are not guaranteed to be the labels scikit-learn gives for the same data. Parity is tested by giving both sides the same starting centres, not by matching the random draws.

Results that match, and results that do not

  • Checked against scikit-learn on committed fixtures: KMeans (given the same starting centres), PCA, and the scalers, at 1e-9. Labels are compared up to relabelling, and PCA sign flips are normalised. The tolerance and the normalisation for each algorithm are in docs/parity.md.
  • Other algorithms have their own fixture tests, listed in docs/parity.md.
  • Not compared to scikit-learn: the forests and StumpForest, which are tested by properties because their random draws differ. Do not expect the same predictions.
  • Not implemented: the NMF cd solver and NNDSVD initialisation, the svd_solver choice and whiten for PCA, and the parallel fit for the forests. An estimator that is not listed in Which estimator is not available here.

Saving models

Use save and load, or pickle, for KMeans, PCA, TruncatedSVD, NMF, Ridge, Lasso, ElasticNet and StumpForest. LogisticRegression, DBSCAN and HDBSCAN do not have a file format yet. The format is documented in docs/model-format.md, and files from earlier format versions still load.

Checking a port

Fit both libraries on the same data with the same settings, and compare the outputs that the algorithm defines exactly: coefficients for Ridge and Lasso, cluster centres for KMeans given the same starting centres, and the explained variance for PCA. Compare classifiers by their predicted labels, not by their internal state.
